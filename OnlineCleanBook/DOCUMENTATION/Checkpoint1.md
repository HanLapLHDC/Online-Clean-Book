## I. PROJECT INFORMATION

### 1. Project Name

Clean Book is an e-commerce website project that focuses on selling books online. The website aims to provide customers with a convenient and easy-to-use platform where they can browse, search for, and purchase books from different categories.

The project focuses on making the online book-buying process simpler by providing clear product information, reasonable navigation, and an organized shopping experience.

### 2. Product Category

Product Category: Books - Online Bookstore

Clean Book specializes in selling books from different fields and categories, including:

| No. | Book Category | Description |
| --- | --- | --- |
| 1 | Literature and Novels | Fiction, novels, short stories, and literary works. |
| 2 | Self-help and Personal Development | Books about life skills, personal growth, and communication. |
| 3 | Economics and Business | Books about economics, business, management, and finance. |
| 4 | Education and Reference | Textbooks, study materials, and reference books. |
| 5 | Science and Information Technology | Books about science, technology, and computer science. |
| 6 | Children's Books | Picture books, educational books, and stories for children. |

Products will be organized into categories to help customers find books more easily. Each book will have basic information such as its title, author, price, description, and available stock.

### 3. Target Customers

Clean Book targets the following customer groups:

| Customer Group | Needs and Interests |
| --- | --- |
| Students | Looking for textbooks, reference materials, and books to support their studies. |
| Working Professionals | Interested in business, professional skills, and personal development books. |
| Book Lovers | Regularly searching for novels, literature, and books from different genres. |

Target Age Group: Primarily 16-35 years old.

These customers are familiar with using the Internet to search for information, compare products, and shop online. They may prefer an online bookstore because it allows them to explore different books and make purchases without visiting a physical store.

### 4. Problem Statement

### 4.1. Existing Problems

Buying books can sometimes be inconvenient for customers, especially when they do not know exactly which book they want or where to find it.

Some common problems include:

Customers may spend a lot of time searching for books that match their interests and needs.

Finding books by title, author, or category may be difficult when product information is not well organized.

Customers may not have enough information about a book's content, price, and availability before making a purchase.

Visiting physical bookstores may be inconvenient for customers who live far away or have limited free time.

### 4.2. Proposed Solution

Clean Book aims to address these problems by developing an online bookstore with a simple and user-friendly interface.

The website will allow customers to:

Browse books by category.

Search for books by title or author.

View detailed information about each book.

Add books to a shopping cart and update quantities.

Place orders online.

View relevant product information before making a purchase.

And more comfortable service if customers need to add in e-shop.

Through these features, Clean Book aims to reduce the time and effort required to buy books, make books easier to access, and provide customers with a more convenient online shopping experience.

### 2. User Flow

The Clean Book website is designed with a simple and user-friendly interface. Its main purpose is to help customers find suitable books and complete their purchases conveniently.

### 2.1. Customer User Flow

The customer shopping process consists of the following steps:

Step 1: The customer visits the Clean Book homepage.

Step 2: The customer searches for books or browses available book categories.

Step 3: The customer selects a book to view its detailed information.

Step 4: The customer adds the selected book to the shopping cart.

Step 5: The customer reviews the shopping cart and checks the selected books.

Step 6: The customer logs in or proceeds with the order process.

Step 7: The customer completes the ordering process.

Step 8: The system confirms that the order has been placed successfully.

### 2.2. Administrator User Flow

The administrator uses the management interface to maintain website information and process customer orders.

Step 1: The administrator logs in to the system.

Step 2: The administrator accesses the Admin Dashboard.

Step 3: The administrator selects a management function, such as managing books, authors, publishers, categories, or orders.

Step 4: The administrator performs the required actions, such as adding, editing, deleting, or viewing records.

Step 5: The system saves the changes to the database and updates the information displayed on the website.

Administrator User Flow:

Admin Login → Admin Dashboard → Select Management Function → Add / Edit / Delete / View Data → Save Changes to Database → Display Updated Information.

### 3. Proposed Technology Stack

The team plans to use common web development technologies that are suitable for the project's scope and the members' current technical knowledge.

| Technology | Purpose |
| --- | --- |
| HTML5 | Builds the structure and content of web pages. |
| CSS3 | Designs the website layout, colors, and visual appearance. |
| JavaScript | Handles user interactions and basic form validation. |
| Bootstrap 5 | Supports responsive interface design. |
| PHP | Handles server-side logic, authentication, and website functions. |
| MySQL | Stores and manages books, authors, publishers, customers, and order data. |
| XAMPP | Provides a local development environment for running and testing the website. |
| Git & GitHub | Manage source code and support team collaboration. |
| Visual Studio Code | Provides an environment for writing and editing source code. |

### 3.1. System Architecture

The system is expected to follow a basic Client–Server Architecture, consisting of three main components:

Frontend: Uses HTML, CSS, Bootstrap, and JavaScript to display the website interface and handle user interactions.

Backend: Uses PHP to process user requests, implement business logic, and communicate with the database.

Database: Uses MySQL to store and manage system information.

When a customer interacts with the website, the frontend sends requests to the PHP backend. The backend processes these requests and retrieves or updates the necessary information in the MySQL database before returning the results to the frontend.

### 3.2. Proposed Database Structure

The initial database is expected to include the following main tables:

| Table | Description |
| --- | --- |
| Books | Stores book information, including book ID, title, price, description, and stock quantity. |
| Authors | Stores author information. |
| Publishers | Stores publisher information. |
| Categories | Stores book categories and their descriptions. |
| Users | Stores customer and administrator accounts, including login information and user roles. |
| Carts | Stores shopping cart information associated with customers. |
| Cart_Items | Stores the books and quantities added to each shopping cart. |
| Orders | Stores customer order information, delivery details, total amount, and order status. |
| Order_Details | Stores the books and quantities included in each order. |

The tables will be connected using primary keys and foreign keys to maintain data relationships and consistency.

### 3.3. Reasons for Technology Selection

The team selected these technologies because they are accessible, have extensive learning resources, and are suitable for developing a small-scale e-commerce website.

HTML, CSS, and JavaScript support the development of an interactive and user-friendly interface. PHP and MySQL provide the necessary tools for server-side processing and data management. Bootstrap helps create a responsive design, while GitHub supports collaboration and source code management among team members.
